# 最低限要件定義（MVP）

## 1. 対象ユーザー
- 待ち合わせ前に短時間で入店可能な店を探したい人
- カフェに限定せず、会話しやすい店を探したい人

## 2. ゴール（今回の実装段階）
- ローカルで起動できるWebサーバー形式で動作すること
- 待ち合わせ地点を入力すると、候補取得→フィルタ→地図プロット→おすすめ一覧表示まで一連動作すること

## 3. 入力
- 待ち合わせ地点（駅名/ランドマーク）
- 利用時刻（今すぐ/指定時刻）
- 人数（任意）
- 利用目的タグ（任意: 会話/作業/デート）

## 4. 出力
- 地図上の候補店ピン表示
- 店舗一覧ランキング（入りやすい順）
- 各候補の最小情報:
  - 店名
  - 待ち合わせ地点からの距離
  - 営業状況
  - 予約可否（即予約可/電話推奨/不明）
  - 混雑推定（低/中/高）
  - 雰囲気タグ
  - 推薦理由（例: 駅近・予約可・混雑低）

## 5. フィルタリング要件（初期）
- 半径フィルタ（例: 800m以内）
- カテゴリフィルタ（カフェ + カフェ利用可能な飲食店 + 条件付きバー）
- 営業中優先（閉店間際は減点）

## 6. スコアリング（初期）
入りやすさスコア = 距離 + 営業中補正 + 予約可否 + 混雑推定 + 雰囲気適合

※ 初期はルールベースで開始し、ユーザー報告データで補正する。

## 7. 非機能要件（最低限）
- 1検索あたり 3 秒以内に候補一覧を表示
- 主要エリア（例: 新宿）で候補漏れを最小化
- 取得元と推定値を明示し、誤認を避ける
- APIキー未設定時でもフィクスチャデータでローカル動作確認できる
