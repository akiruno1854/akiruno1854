# 最低限テストケース

## 0. 参照ドキュメント
- 外部API処理フロー: `docs/external-api-flow-and-io.md`
- Input/Output詳細ケース: `docs/test-cases-input-output.md`

## 1. ユニットテスト（必須）
1. 距離計算が正しい（基準座標に対して期待距離内）
2. 営業状態の判定が正しい（営業時間境界値）
3. カテゴリフィルタが正しい（カフェ利用可飲食店を含む）
4. スコア算出が単調性を満たす（近い/予約可/混雑低が高得点）

## 2. 統合テスト（必須）
1. `POST /api/search` が200を返す
2. レスポンスに `map_markers` と `ranked_places` が含まれる
3. ランキングが `easiness_score` 降順である
4. 外部連携失敗時にfixtureフォールバックで結果を返せる
5. バリデーションエラー時に422を返せる

## 3. E2Eテスト（最低1本）
1. 地点入力→検索→地図ピン表示→一覧表示が完了する
2. 条件変更（例: 人数/目的タグ）で候補が変化する

## 4. 性能テスト（最低ライン）
1. fixture 50件でAPI応答3秒以内
2. 同条件連続検索時にキャッシュヒットが機能する（将来導入時）

## 5. 受け入れ基準（MVP）
- ローカルでWebサーバー起動し、ブラウザで検索体験が一通り完了する
- エラー時にユーザーが理解可能なメッセージを表示する
- 最低限テスト（unit/integration/e2e）をCIで再現可能にする
- I/O基準ケース（`test-cases-input-output.md`）の正常系がPassしている
